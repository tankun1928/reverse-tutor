# ตัวอย่างการใช้งาน (Quick mode, 3 คำถาม)

> โค้ดที่ใช้: [`examples/demo/cart.js`](demo/cart.js)

---

**คุณ:** สอบฉันหน่อยเรื่อง cart.js

**Claude:** ได้เลย จะสอบเรื่อง `fetchPrice` กับ `cartTotal` ใน `cart.js` นะครับ เอาแบบไหนดี: quick (3 ข้อ), standard (5 ข้อ, ค่าเริ่มต้น) หรือ deep (8 ข้อ)?

**คุณ:** quick

**Claude:** **ข้อ 1 (Predict):** ถ้าเรียก `fetchPrice("A1")` แล้ว API ล่มตลอด (ตอบ 500 ทุกครั้ง) และใช้ค่า `retries` ตั้งต้น ฟังก์ชันจะยิง request ไปทั้งหมดกี่ครั้ง และรอระหว่างครั้งนานเท่าไหร่?

**คุณ:** 2 ครั้ง รอ 200ms

**Claude:** 🟡 **เกือบแล้ว** จับได้ถูกว่ามีการรอแบบเพิ่มขึ้นเรื่อยๆ ลองดูเงื่อนไขลูปบรรทัด 6 อีกที: `attempt <= retries` เมื่อ `retries = 2` ค่า `attempt` จะวนเป็นค่าอะไรบ้าง?

**คุณ:** อ๋อ 0,1,2 งั้นยิง 3 ครั้ง รอ 200 กับ 400

**Claude:** ✅ **ถูกต้อง** ยิง 3 ครั้ง (ครั้งแรก + retry 2 ครั้ง) รอ `2 ** attempt * 200` คือ 200ms และ 400ms ส่วนครั้งสุดท้ายไม่รอ เพราะโยน error ออกไปเลย (บรรทัด 14) แบบนี้เรียกว่า *exponential backoff*

**ข้อ 2 (Why):** ทำไม `cartTotal` ใช้ `Promise.all` แทนการ `await` ทีละชิ้นในลูป `for`?

**คุณ:** ไม่รู้ครับ

**Claude:** ❓ ไม่เป็นไรครับ อธิบายสั้นๆ: `Promise.all` ยิง request **ทุกชิ้นพร้อมกัน** แล้วรอจนครบ ถ้ามี 10 ชิ้น ชิ้นละ 300ms จะใช้เวลารวมประมาณ 300ms แต่ถ้า `await` ทีละชิ้นจะกลายเป็นประมาณ 3 วินาที
ข้อแลกเปลี่ยนคือถ้ามีชิ้นไหนล้มเหลวแม้แต่ชิ้นเดียว `Promise.all` จะ reject ทั้งก้อน ทำให้ไม่ได้ยอดรวมเลย
ลองเองได้: ใส่ `console.time` ครอบทั้งสองแบบแล้วเทียบเวลาดูครับ

**ข้อ 3 (Predict - ทำงานพร้อมกัน):** ถ้าตะกร้ามีสินค้า SKU `"A1"` อยู่ 2 แถว ตอนแคชยังว่าง จะยิง request ไปหา `"A1"` กี่ครั้ง?

**คุณ:** ครั้งเดียว เพราะมี cache

**Claude:** ❌ **ยังไม่ใช่ครับ** hint: ลองดูว่า `cache.set` เกิดขึ้นตอนไหน (บรรทัด 11) เทียบกับตอนที่ `Promise.all` เรียก `fetchPrice` ทั้งสองครั้ง (บรรทัด 21) ตอนที่เรียกครั้งที่สอง แคชมี `"A1"` หรือยัง?

**คุณ:** น่าจะมีแล้วมั้ง เพราะครั้งแรกเรียกไปก่อน

**Claude:** ยังไม่มีครับ อันนี้เป็นจุดที่หลายคนพลาดกัน
ทั้งสองครั้งถูกเรียกพร้อมกัน **ก่อน** ที่ request แรกจะตอบกลับ ตอนนั้นแคชยังว่าง เลยยิงไป 2 ครั้ง ปัญหานี้เรียกว่า *cache stampede*
วิธีแก้คือเก็บ **Promise** ลงแคชแทนการเก็บราคา

> ⚠️ **ข้อสังเกตเรื่องโค้ดจริง:** แคชนี้ไม่มีวันหมดอายุ ถ้าราคาเปลี่ยน ผู้ใช้จะเห็นราคาเก่าไปจนกว่าจะรีสตาร์ตเซิร์ฟเวอร์ ควรเพิ่ม TTL
